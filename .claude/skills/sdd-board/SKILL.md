# SDD Board

The board is the **source of truth for story state** between `/breakdown` and `/ship`. Task files are plain markdown; the script only reads and edits their frontmatter.

## Layout

```text
.claude/sdd/board/{FEATURE}/
├── S01-short-slug.md     # one task per story
├── S02-short-slug.md
├── _log.md               # append-only audit trail (written by board.py move)
└── BOARD.html            # generated by `board.py html`, never edit
```

`{FEATURE}` is the same slug used under `.claude/sdd/features/`.

## Task file contract

```markdown
---
id: S01
feature: {FEATURE}
title: "Short imperative title"
status: backlog
depends_on: []
agent: python-developer
files: [src/a.py, tests/test_a.py]
updated: 2026-09-29
---

## Description
## Actual Plan
## Architecture
## Acceptance Criteria
- [ ] ...
```

- `id`: `S` + two digits, unique per feature. `depends_on`: inline list of ids, e.g. `[S01, S02]`.
- `agent`: specialist from the DESIGN file manifest, empty if general.
- Frontmatter is flat `key: value`. No nested YAML — `board.py` does not parse it.

## Statuses and transitions

`backlog · ready · in-progress · review · done · blocked`

| From | To |
|------|----|
| backlog | ready, blocked |
| ready | backlog, in-progress, blocked |
| in-progress | ready, review, blocked |
| review | in-progress, done, blocked |
| done | review (reopen) |
| blocked | backlog, ready, in-progress |

Rules enforced by `move` (bypass only with `--force`, and say why in `--note`):
- `ready` / `in-progress` require every `depends_on` task to be `done`.
- `blocked` requires `--note`.
- Moving a task to `done` auto-promotes dependents in `backlog` whose deps are all done to `ready`.
- Acceptance Criteria checkboxes must all be ticked before the move to `done` — verified by the agent, not the script.

## Commands

Run from the `.claude/` parent directory (script path is relative to the plugin/config root):

```bash
python .claude/skills/sdd-board/board.py list
python .claude/skills/sdd-board/board.py show  {FEATURE}
python .claude/skills/sdd-board/board.py next  {FEATURE}
python .claude/skills/sdd-board/board.py move  {FEATURE} S01 in-progress
python .claude/skills/sdd-board/board.py move  {FEATURE} S02 blocked --note "waiting on Open Question #1"
python .claude/skills/sdd-board/board.py check {FEATURE}    # cycles, unknown deps, invalid status, done-with-open-deps
python .claude/skills/sdd-board/board.py html  {FEATURE}    # writes BOARD.html (static, self-contained; click a card for the detail panel)
```

Exit code is non-zero on any `check` problem or illegal `move`.

## How other phases use it

| Phase | Obligation |
|-------|------------|
| `/breakdown` | Writes one task file per story (`backlog`, or `ready` when `depends_on` is empty), then runs `check`. Must not leave a failing board. |
| `/validate` | Reads task files as the stories. Reports drift; never edits status. |
| `/build` | If a board exists for the feature, builds **from tasks, not from the manifest**: `next` → `move in-progress` → implement → tick criteria → `move review` → verify → `move done`. |
| `/ship` | Refuses to ship while any task is not `done`. Archives the board directory. |
| `/iterate` | Design or define change that invalidates stories: mark affected tasks `blocked` with a note; `/breakdown` reconciles. |

## Anti-patterns

- Editing `status:` by hand in a task file — use `move`, so the log and promotion stay correct.
- Starting a task whose dependency is not `done` with `--force` to "save time".
- Putting more than one mergeable PR in one task.
- Keeping story text in a separate `stories.md` — the task files are the stories.
